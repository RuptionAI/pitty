What this build already checks, quoted as Pitty prints it.

Y run once · N / Enter decline
Ask is the mode Pitty starts in. File changes, commands, and reads of credential-like files wait on screen until you answer. Y runs that one action once; the next one asks again.
File changed after approval; prepare the edit again.
Pitty compares the file with the version you reviewed. If anything changed after you said yes, the write does not land.
This path may contain credentials; approved contents will be sent to the model.
Files such as .env and SSH keys need their own approval, and search skips them. Over MCP, they are never read.
Only a small set of nonsecret environment variables is inherited.
Commands the model asks for start from a cleared environment, so OPENROUTER_API_KEY, OPENAI_API_KEY, and PITTY_API_KEY stay out. They still run with your account’s permissions, and Ctrl+C stops the whole process group.

Any model. The same review.

Chat goes wherever you point it. The review in front of each action stays.

pitty
OpenRouter, the default: free models, the live catalog, web search, and PDFs. Paste a key with /key, or set OPENROUTER_API_KEY.
pitty --interface openai --model gpt-4.1-mini
OpenAI. You name the model, and the key is OPENAI_API_KEY.
pitty --interface compatible --base-url http://127.0.0.1:11434/v1 --model llama3.2
Any endpoint that speaks the same chat protocol, including one on your own machine. A key is optional.
pitty --mcp --directory /path/to/project --tools ask
Or lend the same file and command tools to an MCP client, such as Claude Code or Codex, which brings its own model.

Every answer is on the record.

What ran stays with the conversation, and every decision goes into a log you can check.

/actions
Lists every action that ran in the conversation, with its output. Stopping a request keeps the work already finished, and /retry never repeats a turn that already changed something.
Chain intact · 12 records · /Users/you/.local/share/pitty/audit.log
What /audit reports. Each approval, decline, and run adds one line to a log on your computer, and each line stores the SHA-256 of the line before it, so an edited or deleted line breaks the chain. It records decisions, never file contents or output. Someone able to rewrite the whole file could build a new chain; the check cannot see that.

Rust all the way down.

How Pitty is built, and what it never does.

  • The terminal interface is Pitty’s own Rust library with no dependencies: its renderer, editor, Unicode layout, and input decoding.
  • Command parsing and conversation checks run in a WebAssembly engine inside the program, with no access to files or the network.
  • No account and no telemetry. Pitty talks to the chat endpoint you choose, and to other Pitty terminals only when you open a /peer room.
  • Downloads come with SHA-256 checksums, and the installer checks them before anything is unpacked.
  • This site is built the same way: a Rust program renders every page, and the demo above runs on Rust compiled to WebAssembly.

Still ahead.

What this build does not do yet, in the order we plan to close it.

  1. A notarized Mac build. Today’s macOS downloads are not signed with an Apple Developer ID.
  2. Windows. Pitty runs on macOS and 64-bit Linux. Windows users can try the Linux build in WSL2; that path is untested.
  3. Streaming replies. A reply appears when the model finishes it.
  4. Rules a team can share. Ask or auto set once for a whole team, with a record everyone can read.
