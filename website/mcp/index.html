Same tools. The client’s model.

The same file and command tools, behind the same approval boundary, in a client that already has a model. No OpenRouter key is used. Ask is read-only: standard input carries the protocol, so Pitty cannot show a Y/N prompt and declines anything that needs one. New here? Install Pitty first.

Add Pitty in one command.

Open a terminal in the project folder you want the client to work in, then run the line for your client. The shell fills in both absolute paths for you.

Claude Code: run in your project folder
claude mcp add pitty -- "$HOME/.local/bin/pitty" --mcp --directory "$PWD" --tools ask

Codex CLI: run in your project folder
codex mcp add pitty -- "$HOME/.local/bin/pitty" --mcp --directory "$PWD" --tools ask

Each command starts Pitty in Ask mode, which exposes read-only tools. Claude Code saves the server for the current project. Codex saves it in ~/.codex/config.toml, which every project shares, so give each additional project its own name, such as pitty-site.

Configure any other client.

Apps such as Claude Desktop and Cursor read a JSON configuration. First print the two absolute paths it needs, from inside your project folder:

Terminal: prints the program path, then the project path
printf '%s\n' "$HOME/.local/bin/pitty"
pwd -P

Then add a local stdio server to the client’s MCP settings, replacing both paths with the ones printed above:

JSON: replace both paths
{
  "mcpServers": {
    "pitty": {
      "command": "/absolute/path/to/pitty",
      "args": [
        "--mcp",
        "--directory", "/absolute/path/to/project",
        "--tools", "ask"
      ]
    }
  }
}

Clients do not expand ~ or $HOME inside JSON, so use the full paths. Some clients use a form instead: set the command, then add each entry in args as its own argument. VS Code names the top-level key servers instead of mcpServers.

Starting pitty --mcp by hand waits silently for protocol messages; it does not open the chat. Your client starts and stops the process.

Choose what the client can do.

ask: read-only tools
List directories, read files, and search text. Anything that would need your approval, including sensitive reads, is declined, because standard input carries MCP messages and cannot show a prompt.
auto: all six tools
Change ask to auto to add file creation, editing, and command execution. Set up confirmation in your MCP client. Credential-like files, such as .env and SSH keys, are never read through MCP in either mode.
ToolWhat it doesMode
list_filesList a directoryAsk / Auto
read_fileRead text from a fileAsk / Auto
search_filesFind text in project filesAsk / Auto
write_fileCreate or overwrite a fileAuto
edit_fileReplace exact textAuto
run_commandRun a command and return its outputAuto

File tools stay inside the project directory you pass; folders connected in the terminal chat do not widen that scope. Commands run with your account’s filesystem and network permissions. Cancellation, a closed connection, and termination signals stop running work and its commands. The client receives every tool result and decides where it goes next.
